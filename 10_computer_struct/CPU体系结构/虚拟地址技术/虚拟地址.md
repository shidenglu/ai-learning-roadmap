# 虚拟地址技术详解


# 1. 什么是虚拟地址


虚拟地址（Virtual Address，VA）是一种由CPU提供给程序使用的地址。

简单理解：

> 程序看到的地址，不是真实物理内存地址，而是一层由操作系统和硬件映射出来的虚拟地址。


程序运行：

```c
int a = 10;

printf("%p",&a);
```


输出：

```
0x7fff12340000
```


这个地址：

```
不是RAM中的真实地址
```


它是：

```
虚拟地址（VA）
```


最终需要经过转换：

```
虚拟地址

     |

     v

物理地址

     |

     v

真实内存
```


---

# 2. 为什么需要虚拟地址


如果没有虚拟地址：

CPU直接访问物理地址：

```
CPU

 |

物理地址

 |

RAM
```


程序直接使用：

```
0x1000
```


访问：

```
RAM地址0x1000
```


这种方式存在很多问题。


---

# 3. 没有虚拟地址的问题


## 3.1 多个程序无法同时运行


假设：

程序A：

```
地址:

0x1000
```


程序B：

```
地址:

0x1000
```


如果直接访问：

```
RAM:

0x1000
```


两个程序冲突。


---

## 3.2 程序需要知道内存布局


没有虚拟地址：

程序必须知道：

```
代码在哪里

数据在哪里

其他程序在哪里
```


程序移植困难。


---

## 3.3 内存不足无法运行大程序


例如：

程序需要：

```
8GB内存
```


但是机器：

```
4GB RAM
```


无法运行。


---

## 3.4 安全性差


一个程序可以直接访问：

```
其他程序的数据
```


导致：

- 数据泄露
- 系统崩溃


---

# 4. 虚拟地址的核心思想


虚拟地址技术：

> 给每个程序创建一个独立的地址空间。


例如：

程序A看到：

```
0x00000000

      |

0xffffffff
```


程序B也看到：

```
0x00000000

      |

0xffffffff
```


但是：

实际映射到不同物理内存。


例如：

```
程序A:

虚拟地址

0x1000

    |

    |

物理地址

0x80001000



程序B:

虚拟地址

0x1000

    |

    |

物理地址

0x90001000

```


两个程序互不影响。


---

# 5. 虚拟地址转换


虚拟地址转换由：

```
MMU
(Memory Management Unit)

内存管理单元
```


完成。


结构：

```
              CPU

               |

               |

          Virtual Address

               |

               |

              MMU

               |

               |

          Physical Address

               |

               |

              RAM

```


---

# 6. MMU工作过程


CPU执行：

```c
load 0x400000
```


CPU产生：

```
VA:

0x400000
```


进入：

```
MMU
```


MMU查询：

```
页表(Page Table)
```


找到：

```
VA

0x400000


对应


PA

0x800000

```


然后访问：

```
物理地址0x800000
```


---

# 7. 页（Page）概念


虚拟地址空间不是一个整体转换。


它被划分成固定大小。


称：

```
Page
页
```


常见：

```
4KB
```


例如：

虚拟空间：

```
0x0000

 |

0x0fff

```

是一页。


下一页：

```
0x1000

 |

0x1fff

```


---

# 8. 页表（Page Table）


页表保存：

```
虚拟页

对应

物理页
```


例如：


```
Virtual Page       Physical Page


0x1000             0x8000


0x2000             0x9000


0x3000             0xa000

```


CPU通过页表完成转换。


---

# 11. TLB（Translation Lookaside Buffer）


问题：

每次访问内存：

都查询页表。


页表在内存：

速度慢。


因此CPU增加：

```
TLB
```


作用：

缓存地址转换。


结构：

```
CPU

 |

TLB

 |

Page Table

 |

Memory

```


---

访问过程：


## TLB命中


```
VA

 |

TLB

 |

PA

```


速度快。


---

## TLB未命中


```
VA

 |

TLB

 |

Page Table

 |

更新TLB

 |

PA

```

# 18. 缺页异常（Page Fault）


如果访问：

没有映射的虚拟地址。


例如：

```
VA:

0x5000

```

```
不存在
```


CPU产生：

```

```


流程：

```
CPU访问

 |

MMU发现不存在

 |

异常

 |

OS处理

 |

加载页面

 |

重新执行

```

|概念|作用|
|-|-|
