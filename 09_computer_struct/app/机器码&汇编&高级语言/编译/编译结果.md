# 编译后如何查看代码段、数据段的大小

## 一、可执行文件的结构

编译链接后生成的可执行文件（Linux 下为 ELF 格式，Windows 下为 PE 格式），内部已经划分好了各个段：

```text
┌─────────────────────────┐
│       ELF Header         │  ← 文件头，描述文件基本信息
├─────────────────────────┤
│   .text（代码段）         │  ← 机器指令
├─────────────────────────┤
│   .rodata（只读数据）     │  ← 常量字符串等
├─────────────────────────┤
│   .data（已初始化数据段）  │  ← 全局变量、静态变量（有初始值）
├─────────────────────────┤
│   .bss（未初始化数据段）   │  ← 全局变量、静态变量（无初始值）
├─────────────────────────┤
│   .symtab（符号表）       │
├─────────────────────────┤
│   .strtab（字符串表）     │
├─────────────────────────┤
│       ...               │
└─────────────────────────┘
```

---

## 二、查看方法（Linux）

### 2.1 size 命令（最简单）

```bash
size hello
```

**输出示例：**

```text
   text    data     bss     dec     hex   filename
   1625     600       8    2233     8b9   hello
```

| 列 | 含义 |
|----|------|
| text | 代码段 + 只读数据段大小（字节） |
| data | 已初始化数据段大小 |
| bss | 未初始化数据段大小 |
| dec | 总大小（十进制） |
| hex | 总大小（十六进制） |

**更详细的格式：**

```bash
size -A hello
```

```text
hello  :
section                size      addr
.interp                  28    4194584
.note.gnu.build-id       36    4194612
.note.ABI-tag            32    4194648
.gnu.hash                28    4194680
.dynsym                 216    4194712
.dynstr                 106    4194928
.text                  1625    4195552
.rodata                 324    4210688
.data                    16    4215296
.bss                      8    4215312
...
Total                  4523
```

### 2.2 objdump 命令（查看段头）

```bash
objdump -h hello
```

**输出示例：**

```text
hello:     file format elf64-x86-64

Sections:
Idx Name          Size      VMA               LMA               File off  Algn
  0 .interp       0000001c  0000000000400238  0000000000400238  00000238  2**0
  1 .note.gnu.build-id 00000024  0000000000400254  ...
  ...
 13 .text         00000659  0000000000400560  0000000000400560  00000560  2**4
 14 .rodata       00000144  0000000000600bc0  ...
 15 .data         00000010  0000000000601010  ...
 16 .bss          00000008  0000000000601020  ...
```

| 列 | 含义 |
|----|------|
| Name | 段名 |
| Size | 大小（十六进制，单位字节） |
| VMA | 虚拟内存地址（加载后的地址） |
| File off | 在文件中的偏移 |

---

### 2.3 readelf 命令（最全面）

#### 查看段头表（Section Headers）：

```bash
readelf -S hello
```

**输出示例：**

```text
Section Headers:
  [Nr] Name              Type            Address          Offset     Size
  [ 0]                   NULL            0000000000000000 00000000 000000
  [ 1] .interp           PROGBITS        0000000000400238 00000238 00001c
  ...
  [13] .text             PROGBITS        0000000000400560 00000560 000659
  [14] .rodata           PROGBITS        0000000000600bc0 00000bc0 000144
  [15] .data             PROGBITS        0000000000601010 00001010 000010
  [16] .bss              NOBITS          0000000000601020 00001020 000008
  ...
```

#### 查看程序头表（Program Headers）：

```bash
readelf -l hello
```

**输出示例：**

```text
Program Headers:
  Type           Offset   VirtAddr           PhysAddr           FileSiz  MemSiz
  LOAD           0x000000 0x0000000000400000 0x0000000000400000 0x000d04 0x000d04  R E
  LOAD           0x000d08 0x0000000000600d08 0x0000000000600d08 0x000228 0x000230  RW
```

> 第一个 LOAD 段（R+X）→ 代码段 + 只读数据
> 第二个 LOAD 段（RW）→ 数据段 + BSS

---

### 2.4 nm 命令（查看符号地址）

```bash
nm hello
```

**输出示例：**

```text
0000000000601010 D global_var        ← D 表示在 .data 段
0000000000601020 B global_uninit     ← B 表示在 .bss 段
0000000000400560 T main              ← T 表示在 .text 段
00000000004006a0 R hello_str         ← R 表示在 .rodata 段
```

| 符号 | 含义 |
|------|------|
| T | 代码段（.text） |
| D | 已初始化数据段（.data） |
| B | 未初始化数据段（.bss） |
| R | 只读数据段（.rodata） |

## 三、查看方法（Windows）

### 3.1 dumpbin（Visual Studio 自带）

```bash
dumpbin /headers hello.exe
dumpbin /sections hello.exe
```

**输出示例：**

```text
SECTION HEADER #1
  .text name
  1A3C virtual size
  1000 virtual address
  1C00 size of raw data
  400 file pointer to raw data

SECTION HEADER #2
  .data name
  258 virtual size
  3000 virtual address
  400 size of raw data
  2000 file pointer to raw data

SECTION HEADER #3
  .rdata name
  ...
```

### 3.2 PowerShell 快速查看

```powershell
# 查看文件大小
Get-Item hello.exe | Select-Object Length
```

## 四、实际示例

### 源代码：

```c
#include <stdio.h>

int global_init = 100;        // → .data
int global_uninit;            // → .bss
const char *msg = "hello";   // "hello" → .rodata, msg指针 → .data

int add(int a, int b) {      // → .text
    return a + b;
}

int main() {                  // → .text
    int local = 10;           // → 栈（不在段中）
    printf("%s %d\n", msg, add(global_init, local));
    return 0;
}
```

### 编译：

```bash
gcc -o hello hello.c
```

### 查看：

```bash
$ size hello
   text    data     bss     dec     hex   filename
   1625     608       8    2241     8c1   hello

$ readelf -S hello | grep -E "text|data|bss|rodata"
  [13] .text          PROGBITS  0000000000400560  00000560  000659  00  AX  0  0  16
  [14] .rodata        PROGBITS  0000000000600bc0  00000bc0  000144  00   A  0  0  8
  [15] .data          PROGBITS  0000000000601010  00001010  000010  00  WA  0  0  8
  [16] .bss           NOBITS    0000000000601020  00001020  000008  00  WA  0  0  1
```

### 解读：

| 段 | 大小 | 内容 |
|----|------|------|
| .text | 0x659 = 1625 字节 | main、add 等函数的机器码 |
| .rodata | 0x144 = 324 字节 | "hello" 字符串、printf格式串 |
| .data | 0x10 = 16 字节 | global_init=100, msg指针 |
| .bss | 0x8 = 8 字节 | global_uninit（未初始化） |

## 五、编译选项对段大小的影响

| 选项 | 效果 |
|------|------|
| `-O0`（默认） | 不优化，代码段较大 |
| `-O2` | 优化后代码段可能变小（内联、消除冗余） |
| `-Os` | 优化代码体积，代码段最小 |
| `-g` | 加入调试信息，文件变大但不影响 text/data 段 |
| `-static` | 静态链接，text 段显著增大（包含库代码） |
| `-fno-stack-protector` | 去除栈保护代码，text 略小 |

```bash
# 对比不同优化级别
gcc -O0 -o hello_O0 hello.c && size hello_O0
gcc -O2 -o hello_O2 hello.c && size hello_O2
gcc -Os -o hello_Os hello.c && size hello_Os
```

---

## 六、总结

| 工具 | 命令 | 适用场景 |
|------|------|----------|
| size | `size hello` | 快速查看 text/data/bss 大小 |
| size -A | `size -A hello` | 查看每个段的详细大小和地址 |
| objdump -h | `objdump -h hello` | 查看段头和地址 |
| readelf -S | `readelf -S hello` | 最全面的段信息 |
| readelf -l | `readelf -l hello` | 查看加载时的段布局 |
| nm | `nm hello` | 查看符号属于哪个段 |
| dumpbin | `dumpbin /sections hello.exe` | Windows 下查看 |

> **一句话总结**：编译链接后，各段的大小和地址已经固定在可执行文件中。Linux 下用 `size` 快速查看，用 `readelf -S` 详细查看；Windows 下用 `dumpbin /sections` 查看。
