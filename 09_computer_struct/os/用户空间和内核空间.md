# 内核空间与虚拟地址的关系


# 1. 基本概念


现代操作系统使用：

```
虚拟地址（Virtual Address）
```

而不是让程序直接访问物理内存。


CPU访问内存：

```
程序

 |

虚拟地址 VA

 |

MMU

 |

物理地址 PA

 |

RAM
```


因此：

> 内核空间也是建立在虚拟地址技术之上的。


---

# 2. 什么是内核空间


内核空间（Kernel Space）：

指：

> 操作系统内核运行时使用的虚拟地址区域。


CPU执行程序时：

地址空间通常划分为：

```
整个虚拟地址空间


+----------------+
|                |
|  Kernel Space  |
|                |
+----------------+

|                |
|  User Space    |
|                |

+----------------+

```


简单理解：

```
用户程序
    |
    |
用户空间


操作系统

    |
    |
内核空间
```

---

# 3. 内核空间不是物理内存


一个常见误区：

认为：

```
内核空间 = 一块固定RAM
```


错误。


实际上：

内核空间也是：

```
虚拟地址范围
```


例如：

Linux：

```
虚拟地址：

0xffff000000000000

        |

        |

内核空间

```


这个地址最终：

通过页表：

映射到：

```
物理内存
```


例如：

```
Kernel VA

0xffff000010000000


        |

        |

Kernel PA


0x80000000

```


---

# 4. 为什么需要内核空间


如果所有程序都能访问硬件：

例如：

```
应用程序

直接访问

GIC
DMA
UART
MMU寄存器
```


会导致：

- 系统崩溃
- 数据破坏
- 安全问题


因此CPU提供权限等级。


---

# 5. CPU权限级别


ARMv8：

```
EL0

用户态

----------------

EL1

内核态

----------------

EL2

Hypervisor

----------------

EL3

安全监控
```


对应：

```
User Space

    |
    |
Kernel Space
```

```
+----------------+

低地址

```

# 7. 用户空间和内核空间的页表


每个进程都有：

```
页表
```


例如：

进程A：

```
Page Table A


用户空间:

VA ---> PA


内核空间:

VA ---> PA
```


进程B：

```
Page Table B


用户空间:

VA ---> PA


内核空间:

VA ---> PA

```


区别：

用户空间不同。


但是：

内核空间通常相同。


---

# 8. 为什么所有进程共享内核空间


例如：

两个进程：

```
Process A


Process B

```


虚拟地址：

```
0xffff000000000000
```


都映射：

```
Kernel Code


Kernel Data


Driver


Memory Manager

```


原因：

系统调用时：

需要快速进入内核。


---

# 9. 系统调用中的地址变化


用户程序：

```c
read(fd,buf,size);
```


执行：

```
用户空间

EL0

 |

系统调用

 |

EL1

 |

内核空间

```


CPU：

切换：

```
权限级别
```


但是：

虚拟地址空间仍然存在。


---

# 10. 用户访问内核地址


例如：

用户程序：

访问：

```
0xffff000000000000
```


MMU检查：

页表权限：

```
User = 0
```


结果：

```
Permission Fault
```


产生异常。


---

# 11. 内核访问用户地址


内核：

可以访问用户空间。


例如：

系统调用：

```
write(fd, user_buffer)
```


用户提供：

```
buf地址
```


内核需要：

读取用户数据。


但是必须检查：

- 地址有效
- 权限正确


Linux：

```
copy_from_user()

copy_to_user()

```

# 13. 内核虚拟地址映射示例

```

       |

       |
```

# 15. TTBR与用户/内核空间


ARMv8 MMU：

有两个页表基地址寄存器：


## TTBR0_EL1


通常：

```
用户空间页表
```


---

## TTBR1_EL1

```
内核空间页表
```

```

 |

 |

+------------+

|            |

TTBR0       TTBR1


User        Kernel

```

# 18. 与DMA的关系


DMA使用物理地址：

```
DMA Controller

 |

Physical Address

 |

Memory

```


但是：

驱动看到的是：

```
Kernel Virtual Address
```


所以需要：

```
Kernel VA

 |

页表

 |

Physical Address

 |

DMA

```


例如：

Linux：

```
dma_alloc_coherent()
```


返回：

```
CPU访问地址

+
DMA物理地址

```


---

# 19. 与隔离系统（Matrix653）的关系


类似ARINC653分区系统：

```
Partition A

Virtual Address Space


Partition B

Virtual Address Space


Kernel

Kernel Address Space

```


每个空间：

通过MMU隔离。


核心：

```
虚拟地址

+

页表权限

+

硬件异常级

```


实现隔离。

## 关键理解


|概念|说明|
|-|-|
|虚拟地址|CPU访问资源的逻辑地址|
|用户空间|普通程序运行区域|
|内核空间|OS运行区域|
|MMU|完成虚拟到物理转换|
|页表|保存地址映射|
|权限位|限制访问|
|TTBR0|用户页表|
|TTBR1|内核页表|
