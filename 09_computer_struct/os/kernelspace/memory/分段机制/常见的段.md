# 分段机制中的常见段


# 1. 什么是段（Segment）


在内存分段机制中：

> 段是按照程序逻辑功能划分出来的一块连续地址空间。


一个程序通常不会把所有内容混在一起，而是划分为：

```
程序地址空间


+----------------+
| 栈段 Stack     |
+----------------+
| 堆段 Heap      |
+----------------+
| BSS段          |
+----------------+
| 数据段 Data    |
+----------------+
| 只读数据段     |
+----------------+
| 代码段 Code    |
+----------------+

```


每个段具有：

- 起始地址（Base）
- 大小（Limit）
- 访问权限（Permission）


---

# 2. 为什么需要划分不同段


如果程序所有内容放在一起：

```
Memory


代码

变量

临时数据

函数调用

```


会产生问题：


## 2.1 权限无法控制


例如：

代码应该：

```
只读
```


变量：

```
可读写
```


如果混在一起：

可能导致：

```
程序修改自己的代码
```


---

## 2.2 生命周期不同


代码：

```
程序启动后一直存在
```


局部变量：

```
函数结束释放
```


动态内存：

```
运行期间申请释放
```


需要不同管理方式。


---

# 3. 代码段（Code Segment）


也叫：

```
Text Segment
.text
```


## 作用


保存：

```
CPU执行的机器指令
```


例如：

C代码：

```c
int add(int a,int b)
{
    return a+b;
}
```


编译后：

```asm
ADD
MOV
RET
```


存放在：

```
代码段
```


---

## 特点


通常：

```
只读

可执行
```


权限：

```
R-X

Read + Execute
```


不允许：

```
Write
```


防止：

代码被修改。


---

# 4. 只读数据段（Read Only Data Segment）


通常：

```
.rodata
```


保存：

程序中的常量。


例如：

```c
char *str="hello";
```


字符串：

```
hello
```


通常放：

```
.rodata
```


---

权限：

```
Read Only
```


例如：

```
R--
```


---

# 5. 数据段（Data Segment）


也叫：

```
.data
```


保存：

已经初始化的全局变量。


例如：


```c
int count = 100;
```


变量：

```
count
```


存储：

```
.data
```


---

特点：

程序启动时：

数据已经存在。


权限：

```
RW-
```


即：

```
Read
Write
```


---

# 6. BSS段


名称：

```
Block Started by Symbol
```


通常：

```
.bss
```


保存：

未初始化的全局变量。


例如：

```c
int value;
```


没有初始化：

```
value
```


放入：

```
.bss
```


---

特点：


程序加载时：

不会从文件读取数据。


只需要：

分配空间。


例如：

```
.bss

100MB

```


文件：

不需要保存100MB内容。


---

# 7. 堆段（Heap Segment）


用于：

动态内存分配。


例如：

```c
int *p;

p = malloc(1024);
```


申请空间：

来自：

```
Heap
```


---

特点：

## 生命周期长


由程序控制：

```c
free(p);
```


释放。


---

## 大小动态变化


例如：

```
Heap


申请

↓

扩大


释放

↓

缩小

```


---

# 8. 栈段（Stack Segment）


用于：

函数调用。


保存：

- 参数
- 局部变量
- 返回地址
- 保存寄存器


例如：

```c
void func()
{

int a;

}
```


变量：

```
a

```


位于：

```
Stack
```


---

特点：

## 后进先出


调用：

```
main

↓

funcA

↓

funcB

```


栈：

```
funcB

funcA

main

```


---

## 自动管理


函数退出：

自动释放。


---

# 9. 共享库段（Shared Library Segment）


现代程序通常使用动态库。


例如：

Linux：

```
libc.so
```


加载：

```
共享库区域
```


多个程序：

共享同一份代码。


例如：


```
Process A

      |
      |
      +---- libc.so


Process B

      |
      |
      +---- libc.so

```


---

# 10. 内存映射段（Memory Mapping Segment）


也叫：

```
mmap区域
```


用途：

- 动态库
- 文件映射
- 大块内存


例如：

```c
mmap()
```


创建区域。


---

高地址


+----------------+

# 12. x86分段机制中的特殊段


x86传统分段：

通过段寄存器选择段。


主要有：


---

# 12.1 CS（Code Segment）


代码段寄存器。


保存：

```
当前执行代码所在段
```


例如：

```
CS:EIP
```


表示：

```
代码段地址 + 指令偏移
```


---

# 12.2 DS（Data Segment）


数据段。


保存：

```
普通数据访问段
```


例如：

变量访问。


---

# 12.3 SS（Stack Segment）


栈段。


保存：

```
函数调用栈
```


例如：

```
SS:ESP
```


表示：

栈地址。


---

# 12.4 ES（Extra Segment）


附加数据段。


早期用于：

字符串操作。


---

# 12.5 FS / GS


特殊段寄存器。


现代系统大量使用。


例如Linux：

```
GS

保存CPU Local数据
```


线程：

```
Thread Local Storage
```


---

# 13. 分段与分页结合


现代CPU：

通常：

分段 + 分页。


例如x86：


```
程序地址


 |

逻辑地址


(segment + offset)


 |

分段


 |

线性地址


 |

分页


 |

物理地址

```

# 14. ARM中的段


ARM架构：

没有传统x86段寄存器。


主要采用：

```
分页机制

+
MMU

```


地址转换：

```
Virtual Address

      |

      |

Page Table

      |

      |

Physical Address

```

# 15. 段和权限控制


不同段：

不同权限。


例如：


|段|权限|
|-|-|
|代码段|R-X|
|只读数据段|R--|
|数据段|RW-|
|BSS|RW-|
|堆|RW-|
|栈|RW-|


---

# 16. 段与虚拟地址的关系


现代系统：

每个段实际上对应：

一段虚拟地址区域。


例如：

```
Virtual Address


0x400000

代码段


0x600000

数据段


0x800000

堆


0x7ffffff

栈

```


经过：

```
MMU

```


映射到：

```
Physical Memory
```


---

# 17. 总结


程序常见段：


|段|作用|典型权限|
|-|-|-|
|Code/Text|机器指令|R-X|
|rodata|常量|R--|
|Data|初始化全局变量|RW-|
|BSS|未初始化变量|RW-|
|Heap|动态内存|RW-|
|Stack|函数调用|RW-|
|Shared Library|动态库|R-X|
|mmap|文件映射|可变|
