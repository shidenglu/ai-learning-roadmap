# 父子进程的关系

## 一、基本概念

在操作系统中，进程之间存在**层次关系**。一个进程可以创建一个或多个新进程，被创建的称为**子进程**，创建者称为**父进程**。

- 每个进程**有且只有一个**父进程（除了系统初始进程）
- 一个进程可以有**多个**子进程
- 所有进程构成一棵**进程树**

---

## 二、进程树结构

### 2.1 Linux 进程树示例

```text
systemd (PID=1)
├── sshd (PID=512)
│   └── sshd (PID=1023)
│       └── bash (PID=1024)
│           ├── gcc (PID=2048)
│           │   └── cc1 (PID=2049)
│           └── firefox (PID=2100)
│               ├── firefox (PID=2101)
│               └── firefox (PID=2102)
├── httpd (PID=600)
│   ├── httpd (PID=601)
│   └── httpd (PID=602)
└── cron (PID=700)
```

### 2.2 关键规则

| 规则 | 说明 |
|------|------|
| 唯一根进程 | Linux 中 PID=1 的 `systemd`（或 `init`） |
| 唯一父进程 | 每个进程只有一个父进程 |
| 多个子进程 | 一个父进程可以有多个子进程 |
| 祖先关系 | 父进程的父进程是祖父进程，依此类推 |

## 三、子进程继承父进程的内容

`fork()` 创建子进程时，子进程会**继承**父进程的许多属性：

### 3.1 继承的内容

| 继承内容 | 说明 |
|----------|------|
| 代码段 | 相同的程序代码（写时复制共享） |
| 数据段 | 全局变量、静态变量的初始值 |
| 堆和栈 | fork 时刻的副本（COW） |
| 打开的文件描述符 | 子进程可以继续读写父进程打开的文件 |
| 环境变量 | 如 PATH、HOME 等 |
| 工作目录 | 当前所在目录 |
| 信号处理方式 | 已注册的信号处理函数 |
| 进程优先级 | nice 值 |
| 用户ID / 组ID | UID、GID |
| 文件权限掩码 | umask |

### 3.2 不继承的内容

| 不继承的内容 | 说明 |
|-------------|------|
| PID | 子进程获得全新的 PID |
| fork() 返回值 | 父进程返回子进程PID，子进程返回0 |
| 锁 | 父进程持有的文件锁、记录锁 |
| 定时器 | 父进程设置的定时器 |
| 挂起的信号 | 父进程未处理的挂起信号集 |
| 内存映射 | 某些特殊的 mmap 映射 |

---

## 四、父子进程的独立性

虽然子进程继承了父进程的内容，但 fork 之后它们是**完全独立**的：

### 4.1 独立的地址空间（写时复制）

```text
fork() 刚完成：
┌─────────────────────┐     ┌─────────────────────┐
│    父进程虚拟空间     │     │    子进程虚拟空间     │
│  ┌───────────────┐  │     │  ┌───────────────┐  │
│  │   代码段       │──┼──┐  │  │   代码段       │──┼──┐
│  │   数据段       │──┼──┤  │  │   数据段       │──┼──┤
│  │   堆          │──┼──┤  │  │   堆          │──┼──┤
│  │   栈          │──┼──┤  │  │   栈          │──┼──┤
│  └───────────────┘  │  │  │  └───────────────┘  │  │
└─────────────────────┘  │  └─────────────────────┘  │
                         │                           │
                         ↓                           ↓
                   ┌─────────────────────────────────┐
                   │     共享的物理内存页面（只读）      │
                   │     （写时复制 COW）              │
                   └─────────────────────────────────┘

某进程写入后：
┌─────────────────────┐     ┌─────────────────────┐
│    父进程虚拟空间     │     │    子进程虚拟空间     │
│         │            │     │            │         │
│         ↓            │     │            ↓         │
│   ┌──────────┐      │     │     ┌──────────┐    │
│   │ 物理页 A  │      │     │     │ 物理页 B  │    │  ← 各自独立
│   └──────────┘      │     │     └──────────┘    │
└─────────────────────┘     └─────────────────────┘
```

### 4.2 独立执行

```text
fork() 之后：
├── 父子进程的执行顺序不确定（取决于调度器）
├── 父进程可能先执行，也可能子进程先执行
├── 两者并发运行，互不阻塞（除非显式同步）
└── 一个进程的崩溃不影响另一个
```

### 4.3 代码验证独立性

```c
#include <stdio.h>
#include <unistd.h>

int global_var = 100;

int main() {
    int local_var = 200;

    pid_t pid = fork();

    if (pid == 0) {
        // 子进程修改变量
        global_var = 999;
        local_var = 888;
        printf("子进程: global=%d, local=%d\n", global_var, local_var);
        // 输出: 子进程: global=999, local=888
    } else {
        sleep(1);  // 确保子进程先执行
        printf("父进程: global=%d, local=%d\n", global_var, local_var);
        // 输出: 父进程: global=100, local=200  ← 不受子进程影响
    }

    return 0;
}
```

> **结论**：fork 后，父子进程各自拥有独立的变量副本，修改互不影响。

## 五、父子进程的同步与等待

### 5.1 父进程等待子进程（wait / waitpid）

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("子进程开始工作, PID=%d\n", getpid());
        sleep(3);  // 模拟工作
        printf("子进程完成\n");
        exit(42);  // 退出码为42
    } else {
        int status;
        printf("父进程等待子进程...\n");

        pid_t child_pid = wait(&status);  // 阻塞等待

        printf("子进程 %d 已结束\n", child_pid);

        if (WIFEXITED(status)) {
            printf("正常退出，退出码 = %d\n", WEXITSTATUS(status));
        }
    }

    return 0;
}
```

**输出：**

```text
子进程开始工作, PID=2049
父进程等待子进程...
子进程完成
子进程 2049 已结束
正常退出，退出码 = 42
```

### 5.2 wait 的作用

| 功能 | 说明 |
|------|------|
| 阻塞等待 | 父进程暂停，直到子进程结束 |
| 回收资源 | 释放子进程的 PCB，避免僵尸进程 |
| 获取退出状态 | 通过 status 参数获取子进程的退出码 |

### 5.3 如果不等待会怎样？

→ 产生**僵尸进程**（详见第七节）

## 六、父进程与子进程的生命周期关系

### 6.1 四种可能的时序

```text
情况1：父进程先结束，子进程后结束（正常）
父进程 ████████
子进程    ████████████
              ↑ 父结束，子被init收养

情况2：子进程先结束，父进程调用wait回收（正常）
父进程 ████████████████
子进程    ████
              ↑ 子结束，父wait回收

情况3：子进程先结束，父进程不wait（僵尸）
父进程 ████████████████
子进程    ████ → 变为僵尸（Z）
              ↑ 子结束但未被回收

情况4：父进程先结束，子进程还在运行（孤儿）
父进程 ████
子进程    ████████████
         ↑ 父结束，子成为孤儿进程
```

## 七、特殊进程状态

### 7.1 僵尸进程（Zombie Process）

| 项目 | 说明 |
|------|------|
| 产生原因 | 子进程退出，但父进程没有调用 wait/waitpid 回收 |
| 状态 | 进程状态为 Z（Zombie） |
| 占用资源 | 不占内存、不占CPU，只占用一个 PCB 表项（PID） |
| 危害 | 大量僵尸进程会耗尽 PID 资源 |
| 解决方法 | 父进程调用 wait()；或父进程退出后由 init 自动回收 |

```c
// 产生僵尸进程
pid_t pid = fork();
if (pid == 0) {
    exit(0);  // 子进程退出
}
// 父进程不调用 wait()
sleep(100);  // 子进程成为僵尸
```

**查看僵尸进程：**

```bash
ps aux | grep Z
# 或
ps -eo pid,ppid,stat,cmd | grep Z
```

### 7.2 孤儿进程（Orphan Process）

| 项目 | 说明 |
|------|------|
| 产生原因 | 父进程先退出，子进程还在运行 |
| 处理方式 | 子进程被 PID=1 的 init/systemd 收养 |
| 危害 | 通常无害，init 会自动 wait 回收 |
| 与僵尸的区别 | 孤儿进程还在运行；僵尸进程已退出但未被回收 |

```c
// 产生孤儿进程
pid_t pid = fork();
if (pid > 0) {
    // 父进程立即退出
    exit(0);
}
// 子进程继续运行，成为孤儿，被init收养
sleep(100);
```

### 7.3 对比总结

| | 僵尸进程 | 孤儿进程 |
|--|---------|---------|
| 进程是否还在运行 | ❌ 已退出 | ✅ 还在运行 |
| 父进程状态 | 还活着但不回收 | 已经退出 |
| 谁负责回收 | 需要父进程 wait | init/systemd 自动回收 |
| 危害 | 占用 PID 资源 | 一般无害 |
| 进程状态标记 | Z (Zombie) | R / S（正常运行） |

## 八、进程终止与回收

### 8.1 进程终止的方式

| 方式 | 说明 |
|------|------|
| 正常退出 | main 函数 return、调用 exit() |
| 异常退出 | 段错误、除零、非法指令等 |
| 被信号杀死 | kill -9 PID（SIGKILL） |
| 被父进程终止 | 父进程调用 kill() |

### 8.2 子进程退出后发生了什么？

```text
子进程调用 exit()
       ↓
关闭所有打开的文件
释放用户态内存
       ↓
向父进程发送 SIGCHLD 信号
       ↓
保留 PCB 中的退出状态（等待父进程读取）
       ↓
进入僵尸状态（Z）
       ↓
父进程调用 wait()
       ↓
读取退出状态
释放 PCB
       ↓
进程彻底消失
```

### 8.3 如何避免僵尸进程？

| 方法 | 说明 |
|------|------|
| 父进程调用 wait/waitpid | 最基本的做法 |
| 忽略 SIGCHLD | `signal(SIGCHLD, SIG_IGN)`，子进程退出后自动回收 |
| 双重 fork | 父进程 fork 后立即 wait，子进程再 fork 一个孙进程后退出 |
| 父进程先退出 | 子进程被 init 收养，init 会自动回收 |

**双重 fork 示例：**

```c
pid_t pid = fork();
if (pid == 0) {
    // 第一个子进程
    pid_t pid2 = fork();
    if (pid2 > 0) {
        exit(0);  // 第一个子进程立即退出
    }
    // 孙进程（被init收养，不会成为僵尸）
    sleep(100);
} else {
    wait(NULL);  // 回收第一个子进程
}
```

## 九、父子进程的通信

| 方式 | 说明 |
|------|------|
| 管道（pipe） | 父进程创建管道，fork 后子进程继承文件描述符 |
| 信号（signal） | 父进程向子进程发送信号（如 SIGTERM） |
| 共享内存 | fork 前 mmap，子进程继承映射 |
| wait 返回值 | 传递退出码（0~255） |
| 文件 | 通过共同打开的文件交换数据 |

## 十、总结

```text
父子进程关系
├── 创建关系
│   ├── fork() 创建子进程
│   ├── 子进程继承父进程的大部分属性
│   └── 每个进程只有一个父进程（除PID=1）
├── 独立性
│   ├── 独立的地址空间（COW）
│   ├── 独立的执行流
│   └── 修改变量互不影响
├── 同步关系
│   ├── 父进程可 wait 等待子进程
│   └── 子进程退出向父进程发送 SIGCHLD
├── 生命周期
│   ├── 僵尸进程：子退出，父未回收
│   └── 孤儿进程：父退出，子被init收养
└── 通信方式
    ├── 管道
    ├── 信号
    ├── 共享内存
    └── 退出码
```

> **一句话总结**：父子进程通过 fork 建立关系，子进程继承父进程的资源副本，但此后各自独立运行。父进程通过 wait 回收子进程，不回收则产生僵尸；父进程先退出则子进程成为孤儿被系统收养。
