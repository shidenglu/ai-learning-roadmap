# 进程的创建

## 一、概述

进程不是凭空产生的，而是由某些事件触发操作系统执行一系列操作来创建的。创建进程的本质是：**操作系统为新进程分配必要的资源，建立PCB，并将可执行程序加载到内存中准备执行。**

---

## 二、引起进程创建的事件

| 触发事件 | 说明 | 举例 |
|----------|------|------|
| 用户登录 | 系统为用户创建一个会话进程 | Linux 登录后创建 shell 进程 |
| 作业调度 | 批处理系统中，调度程序从磁盘加载作业 | 作业调度创建新进程 |
| 提供服务 | 用户请求某项系统服务 | 请求打印时，OS 创建打印进程 |
| 应用请求 | 运行中的进程主动创建子进程 | 编译进程创建子进程来编译各源文件 |
| 系统初始化 | 操作系统启动时创建系统进程 | Windows 启动时创建 `svchost.exe`、`explorer.exe` |

---

## 三、进程创建的过程

操作系统创建进程时，依次完成以下步骤：

```text
步骤1：申请空白PCB
        ↓
步骤2：为新进程分配资源
        ├── 分配内存空间（代码段、数据段、堆、栈）
        ├── 分配I/O设备（如需要）
        └── 分配其他系统资源
        ↓
步骤3：初始化PCB
        ├── 设置进程标识符（PID）
        ├── 设置父进程标识符（PPID）
        ├── 设置程序计数器（PC）指向程序入口
        ├── 设置栈指针（SP）
        ├── 设置优先级
        ├── 设置初始状态为"就绪"
        └── 初始化资源清单
        ↓
步骤4：将可执行程序加载到内存
        ├── 加载代码段
        ├── 加载数据段
        └── 建立地址映射（虚拟地址 → 物理地址）
        ↓
步骤5：将新进程插入就绪队列
        ↓
步骤6：等待调度程序分配CPU
```

## 四、进程创建的系统调用

### 4.1 Linux / Unix 系统

#### （1）fork()

- **功能**：创建一个子进程，子进程是父进程的**副本**
- **特点**：
  - 调用一次，返回两次
  - 父进程中返回子进程的 PID（> 0）
  - 子进程中返回 0
  - 出错返回 -1
- **子进程继承父进程的内容**：
  - 代码段、数据段、堆、栈
  - 打开的文件描述符
  - 环境变量
  - 工作目录
- **写时复制（COW, Copy-On-Write）**：
  - fork 后父子进程共享同一份物理内存
  - 任何一方写入时才真正复制，节省资源

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        // 创建失败
        printf("fork failed\n");
    } else if (pid == 0) {
        // 子进程
        printf("我是子进程，PID = %d\n", getpid());
    } else {
        // 父进程
        printf("我是父进程，PID = %d，子进程PID = %d\n", getpid(), pid);
    }
    return 0;
}
```

#### （2）exec() 系列

- **功能**：用一个新的程序**替换**当前进程的代码段和数据段
- **不创建新进程**，而是改变当前进程执行的内容
- 常与 fork 配合使用：fork 创建子进程 → exec 加载新程序

```c
#include <unistd.h>

// 在子进程中执行新程序
if (pid == 0) {
    execl("/bin/ls", "ls", "-l", NULL);
    // 执行到这里说明 exec 失败
    printf("exec failed\n");
}
```

#### （3）fork + exec 组合（典型模式）

```text
父进程调用 fork()
       ↓
子进程诞生（父进程的副本）
       ↓
子进程调用 exec()
       ↓
子进程的代码被替换为新程序
       ↓
子进程开始执行新程序
```

### 4.2 Windows 系统

#### CreateProcess()

- **功能**：一步完成"创建进程 + 加载程序"
- 相当于 Linux 中 fork + exec 的合体
- 参数包括：
  - 可执行文件路径
  - 命令行参数
  - 安全属性
  - 创建标志
  - 启动信息（窗口属性等）

```c
#include <windows.h>

STARTUPINFO si = { sizeof(si) };
PROCESS_INFORMATION pi;

CreateProcess(
    "C:\\Windows\\notepad.exe",  // 可执行文件
    NULL,                         // 命令行参数
    NULL,                         // 进程安全属性
    NULL,                         // 线程安全属性
    FALSE,                        // 不继承句柄
    0,                            // 创建标志
    NULL,                         // 环境变量
    NULL,                         // 工作目录
    &si,                          // 启动信息
    &pi                           // 接收新进程/线程信息
);
```

## 五、父子进程关系

### 5.1 进程树

```text
              init (PID=1)
             /    |    \
          bash   sshd   httpd
          /  \
      gcc   firefox
       |
      cc1
```

- Linux 中所有进程的祖先都是 `init`（PID=1）或 `systemd`
- Windows 中根进程为 `System`（PID=4）和 `smss.exe`

### 5.2 父进程与子进程的关系

| 方面 | 说明 |
|------|------|
| 地址空间 | fork后共享（COW），exec后独立 |
| 文件描述符 | 子进程继承父进程打开的文件 |
| 执行顺序 | 不确定，取决于调度 |
| 终止关系 | 父进程可等待子进程结束（wait） |
| 孤儿进程 | 父进程先终止，子进程被 init/systemd 收养 |
| 僵尸进程 | 子进程结束但父进程未调用 wait 回收 |

## 六、进程创建中的关键问题

### 6.1 资源分配

| 资源 | 处理方式 |
|------|----------|
| 内存 | 分配新的虚拟地址空间 |
| 文件 | 可选择继承或重新打开 |
| CPU | 暂不分配，等待调度 |
| I/O设备 | 按需分配 |

### 6.2 写时复制（COW）

```text
fork() 后：
┌─────────────────────────────────────┐
│  父进程和子进程共享同一物理页面       │
│  页面标记为"只读"                    │
└─────────────────────────────────────┘
          ↓ 某进程尝试写入
┌─────────────────────────────────────┐
│  触发缺页中断                        │
│  OS 复制该页面                       │
│  各自拥有独立副本                    │
└─────────────────────────────────────┘
```

**优点**：避免不必要的复制，提高 fork 效率。

### 6.3 vfork()（Linux特有）

- 与 fork 类似，但子进程**共享**父进程的地址空间
- 子进程先运行，父进程阻塞等待
- 子进程调用 exec 或 exit 后，父进程才继续
- 目的：在子进程立即调用 exec 时避免复制开销

## 七、创建进程的完整流程图

```text
用户/父进程发出创建请求
         │
         ↓
操作系统接收请求
         │
         ↓
┌─────────────────────┐
│  1. 分配空白PCB       │
│  2. 分配唯一PID       │
│  3. 分配内存空间      │
│  4. 加载可执行程序    │
│  5. 初始化PCB         │
│     - PID / PPID     │
│     - PC → 入口地址   │
│     - SP → 栈顶      │
│     - 状态 = 就绪     │
│  6. 建立父子关系      │
│  7. 插入就绪队列      │
└─────────────────────┘
         │
         ↓
    等待调度执行
```

## 八、总结

| 要点 | 内容 |
|------|------|
| 谁创建进程 | 操作系统（应请求而执行） |
| 触发源 | 用户操作、父进程调用、系统服务、作业调度 |
| 创建本质 | 分配PCB + 分配资源 + 加载程序 + 初始化 |
| Linux方式 | fork() + exec() |
| Windows方式 | CreateProcess() |
| 关键优化 | 写时复制（COW） |
| 进程存在的标志 | PCB |

> **一句话总结**：进程的创建是操作系统应请求执行的"分配资源 → 加载程序 → 初始化PCB → 加入就绪队列"的过程，核心系统调用在 Linux 中是 `fork + exec`，在 Windows 中是 `CreateProcess`。
