# 内存分段技术详解


# 1. 什么是内存分段


内存分段（Memory Segmentation）是一种早期计算机内存管理技术。


它的核心思想：

> 将程序按照逻辑结构划分成多个区域，每个区域称为一个段（Segment），CPU通过段号和段内偏移访问数据。


例如一个程序通常包含：

```
程序

+----------------+
| 代码段 Code    |
+----------------+
| 数据段 Data    |
+----------------+
| 堆 Heap        |
+----------------+
| 栈 Stack       |
+----------------+

```


每个区域作为一个独立的段进行管理。


---

# 2. 为什么需要内存分段


最早的计算机：

CPU直接访问物理地址。


结构：

```
CPU

 |

物理地址

 |

Memory

```


例如：

程序A：

```
代码：

0x1000

数据：

0x2000
```


问题：

## 2.1 程序必须固定位置


如果另一个程序加载：

```
0x1000
```


发生冲突。


---

## 2.2 程序无法独立管理


代码、数据、堆、栈混在一起：

```
Memory


代码

数据

变量

栈

```


难以保护。


---

## 2.3 多任务困难


多个程序同时运行：

需要：

```
隔离

保护

重定位
```


因此出现：

内存分段。


---

# 3. 分段的基本思想


程序被划分为多个段：


```
程序


代码段(Code Segment)

数据段(Data Segment)

堆段(Heap Segment)

栈段(Stack Segment)

```


每个段：

拥有：

- 起始地址
- 长度
- 权限


例如：


```
代码段：

Base:
0x100000

Limit:
64KB


数据段：

Base:
0x200000

Limit:
32KB

```


---

# 4. 逻辑地址


分段系统中：

程序使用：

```
逻辑地址
```


逻辑地址由：

```
段号 + 段内偏移
```


组成。


例如：

```
段号:

Code Segment


偏移:

0x100

```


表示：

```
代码段起始地址+0x100
```


---

# 5. 段表（Segment Table）


操作系统维护：

```
段表
```


保存：

```
段号

对应信息
```


例如：


|段号|Base地址|长度|权限|
|-|-|-|-|
|0|0x100000|64KB|RX|
|1|0x200000|32KB|RW|
|2|0x300000|16KB|RW|


---

# 6. 地址转换过程


逻辑地址：

```
(segment, offset)

```


转换：

```
          CPU

           |

       逻辑地址

           |

       查询段表

           |

      Base + Offset

           |

      物理地址

           |

        Memory

```


计算：

```
物理地址 = 段基址 + 段内偏移
```


---

# 7. 举例说明


假设：


段表：

```
代码段:

Base=0x100000


```


CPU访问：

```
Code:0x200
```


转换：

```
Physical Address

=

0x100000+0x200


=

0x100200

```


最终访问：

```
0x100200
```


---

# 8. 分段实现内存保护


段表中保存权限。


例如：


代码段：

```
Read
Execute

```


数据段：

```
Read
Write

```


如果程序：

修改代码：

```
Code Segment + Write

```


CPU检查：

```
Write权限不存在
```


产生异常。


---

# 9. 分段实现程序隔离


进程A：

```
Code Segment

Base=0x100000

```


进程B：

```
Code Segment

Base=0x500000

```


两个程序：

逻辑地址：

```
Code:0x100
```


一样。


但是：

物理地址：

不同。

# 13. 分段的问题


虽然分段解决了很多问题，但是存在缺陷。


---

## 13.1 外部碎片


例如：


内存：

```
+----+
|A   |
+----+

+----+
|空闲|
+----+

+----+
|B   |
+----+

```


虽然总空闲：

```
100MB
```


但是：

连续空间不足。


无法分配大段。


---

## 13.2 段大小不固定


不同程序：

```
代码段大小不同

数据段大小不同
```


管理复杂。


---

## 13.3 内存利用率低


段需要：

连续物理空间。


---

# 14. 分页技术的出现


为了解决分段问题：

出现：

```
分页（Paging）
```


分页：

将内存划分成固定大小。


例如：

```
4KB Page
```


不要求连续空间。


---

# 15. 分段和分页对比


|特点|分段|分页|
|-|-|-|
|单位|段|页|
|大小|可变|固定|
|依据|程序逻辑结构|物理管理|
|地址组成|段号+偏移|页号+偏移|
|碎片|外部碎片|内部碎片|
|保护|天然支持|通过页表权限|
|现代使用|较少|主流|


---

# 17. Linux中的分段


现代Linux主要使用分页。

```

DS

SS

```

```

```


# 21. 总结


## 分段核心思想


```

通过段表完成地址转换

```
